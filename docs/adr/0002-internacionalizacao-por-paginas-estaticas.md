# Internacionalização por páginas estáticas por idioma

O site tem duas URLs canônicas por idioma — `/` em pt-BR e `/en/` em inglês — geradas a partir de uma única fonte: o `index.html` em PT + o dicionário `shared/i18n.ts`. Um script pós-build (`scripts/gerar-pagina-en.js`, executado ao final do `npm run build`) produz `dist/en/index.html` a partir do `dist/index.html`, traduzindo os marcadores `data-i18n`, o head de SEO (lang, title, meta OG/Twitter, canonical, og:locale) e prefixando `../` nos assets relativos.

Escolhemos páginas estáticas por idioma em vez de i18n só em runtime: é o único caminho que indexa as duas línguas de verdade (hreflang + sitemap com alternates). Em vez de Vite multi-page com dois HTMLs mantidos à mão (duplicação de conteúdo), a versão EN é derivada do mesmo HTML — uma fonte única, como o próprio sitemap. As strings dinâmicas (feedback do formulário, toasts, aria-labels) são traduzidas em runtime pelo `js/i18n.ts`; o backend responde no idioma do visitante pelo header `x-lang` (fallback PT). A preferência fica em `localStorage["idioma"]` e um script anti-FOUC (`idioma-inicial.js`) redireciona para o idioma salvo (ou o do navegador na primeira visita) antes do render.
